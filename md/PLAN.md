# 내차일기 기획서

> 내 차의 주행·주유·정비·보험 이력을 한 곳에 기록하고, 필요한 시점에 알려주는 차량 관리 웹앱
> 와이어프레임 3D 차량과 채팅창으로 기록·조회하는 대화형 UI (React + Spring Boot + PostgreSQL + GPT API)
> 작성일: 2026-11-06 / 상태: 초안 v0.2

---

## 1. 배경 및 목적

### 1.1 문제 정의
- 정비·주유·보험·세금 기록이 영수증, 메모, 카드 내역 등에 흩어져 있다.
- 엔진오일, 타이어, 자동차 검사, 보험 만기 등 **시점을 놓치기 쉽다.**
- 실제 차량 유지비(월/연, km당)를 파악하기 어렵다.

### 1.2 목표
1. 차량별 모든 이력을 **1분 내 입력**할 수 있는 간편 기록
2. 소모품 교체·검사·보험 만기를 **자동 알림**
3. 유지비·연비 **통계 시각화**

### 1.3 성공 지표 (MVP 기준)
| 지표 | 목표 |
|---|---|
| 기록 1건 입력 소요 시간 | 30초 이내 |
| 주간 재방문율 | 40% 이상 |
| 알림 후 정비 기록 전환율 | 30% 이상 |

### 1.4 핵심 컨셉: 대화형 차량 관리
메뉴와 폼을 헤매지 않고, **차를 보며 말로 기록하고 묻는** 앱이다.
- "오늘 주유 5만원 40리터, 주행거리 52,300" → AI가 해석해 주유 기록으로 저장
- "엔진오일 언제 갈아야 해?" → 저장된 이력을 근거로 답변
- "이번 달 유지비 얼마야?" → 통계를 조회해 답변

## 4. 주요 사용자 시나리오

1. **주유 후 기록**: 주유소에서 앱 열기 → 금액·주유량·주행거리 입력 → 저장 즉시 연비 표시
2. **교체 시기 알림**: 엔진오일 주기(10,000km) 도달 임박 → 알림 수신 → 정비 후 기록 → 주기 자동 리셋
3. **만기 관리**: 보험 만기 30일/7일 전 알림 → 갱신 후 만기일 업데이트
4. **월말 점검**: 대시보드에서 월 유지비·항목별 비율 확인

## 5. 화면 구성 (IA)

### 5.0 초기 페이지 (랜딩 = 메인)
```
┌──────────────────────────────────────┐
│  내차일기                 [차량▼] [⚙] │
│                                      │
│        ┌──────────────────┐          │
│        │  와이어프레임     │          │
│        │  3D 차량 (회전)   │  ← 화면 중앙│
│        └──────────────────┘          │
│     주행거리 52,300km · 연비 11.2km/L │
│                                      │
│  ┌────────────────────────────────┐  │
│  │ 오늘의 주행은 어땠나요?   [↑]│  ← 하단 고정 채팅창
│  └────────────────────────────────┘  │
└──────────────────────────────────────┘
```
- **차량 비주얼**: 와이어프레임(메시) 스타일의 3D 차량을 중앙에 배치. 천천히 자동 회전, 드래그로 직접 회전.
  - 구현: Three.js(react-three-fiber) + 라이선스가 확보된 GLB 모델에 wireframe 재질 적용. 참고 이미지는 스톡 사진이므로 **직접 사용하지 않고** 무료/유료 3D 모델을 사용한다.
  - 상태 연동(후속): 정비 필요 부위(타이어, 엔진룸 등)를 차량 위에서 강조 표시.
- **채팅창**: Claude 같은 단순한 입력창 + 답변 스트리밍. 입력하면 차량이 위로 줄고 대화 영역이 펼쳐지는 방식.
- **대화 결과 카드**: 기록 저장 시 "주유 기록 저장됨 · 연비 11.4km/L" 같은 확인 카드를 대화에 표시하고 수정/취소 가능.
- 기존 폼 기반 화면(기록, 일정, 통계)은 보조 화면으로 유지한다.

### 5.1 전체 구조

```
홈(대시보드)
├─ 차량 선택 / 요약 카드 (주행거리, 평균 연비, 이번 달 지출)
├─ 다가오는 일정 (소모품·검사·보험)
└─ 빠른 기록 버튼 [주유] [정비] [기타 비용]

기록
├─ 타임라인 (전체 이력, 유형·기간 필터)
└─ 기록 상세 / 수정

소모품·일정
├─ 소모품 목록 (잔여 km / 잔여 일수 게이지)
└─ 주기 설정, 만기일 설정

통계
├─ 월별/연별 지출, 항목별 비율
└─ 연비 추이, km당 비용

내 차
├─ 차량 정보 편집, 차량 추가
└─ 설정 (알림, 단위, 백업)
```

## 8. 기술 스택 (제안)

| 영역 | 제안 | 비고 |
|---|---|---|
| 프론트엔드 | React + Vite + TypeScript | 3D는 Three.js(react-three-fiber), PWA 플러그인 |
| 백엔드 | Java 21 + Spring Boot (Web, Data JPA, Security, Validation) | REST API + SSE(채팅 스트리밍) |
| DB | PostgreSQL | 마이그레이션은 Flyway |
| AI | GPT API (OpenAI) | 백엔드에서만 호출, 키는 서버 환경변수 |
| 인증 | Spring Security + JWT, 소셜 로그인(Google, Kakao) | |
| 알림 | Web Push + 이메일 | 스케줄러(@Scheduled)로 만기 판단 |
| 배포 | Docker Compose(앱 + DB), 클라우드는 추후 결정 | |

### 8.1 GPT 연동 설계
```
[React 채팅창] → POST /api/chat (SSE)
      → [Spring Boot] 대화 + 차량 컨텍스트 구성
      → [GPT API] function calling(tool)
           ├ add_fuel_log / add_maintenance_log / add_expense
           ├ get_next_services / get_stats / get_logs
      → 도구 실행 결과를 DB에 반영 → 최종 답변을 스트리밍
```
- **Function calling 방식**: 자연어를 구조화된 호출로 변환해 DB에 기록. 모델이 DB에 직접 접근하지 않고, 서버가 검증한 도구만 실행한다.
- **확인 단계**: 쓰기 작업은 저장 후 확인 카드로 보여주고 되돌리기 제공. 모호한 입력(금액·거리 누락)은 되물음.
- **컨텍스트**: 선택된 차량 정보, 최근 기록 요약, 소모품 상태만 전달해 토큰과 비용을 절감.
- **비용·안전**: 사용자별 일일 호출 한도, 입력 길이 제한, 프롬프트 인젝션 방지(도구 인자 서버 검증), 개인정보(번호판 등) 최소 전송.
- **모델**: 빠르고 저렴한 모델로 시작하고, 설정으로 교체 가능하게 추상화한다.

### 8.2 프로젝트 구조(제안)
```
mycar/
├─ frontend/   (Vite + React)
├─ backend/    (Spring Boot, Gradle)
├─ docker-compose.yml  (postgres)
└─ PLAN.md
```

> 확정 전 검토 필요: 알림 채널(웹푸시 iOS 제약), 3D 모델 라이선스.

## 11. 수익화 고려사항

광고 등으로 수익이 발생해도 기술 스택 비용은 늘지 않는다. 주의할 부분은 아래와 같다.

| 항목 | 내용 |
|---|---|
| Java | OpenJDK 배포판(Eclipse Temurin 등)을 사용하면 상업적 사용도 무료. 유료인 것은 Oracle JDK 라이선스뿐 |
| Spring Boot, PostgreSQL, React, Vite, Three.js | Apache 2.0 / PostgreSQL / MIT 라이선스, 상업적 사용 무료 |
| 3D 차량 모델 | 상업적 사용이 허용된 모델만 사용(CC0, CC-BY, 구매 라이선스). "개인/비상업 전용" 모델 금지. 스톡 이미지·워터마크 자료 사용 금지 |
| GPT API 비용 | 사용량 과금. 광고 수익보다 채팅 비용이 크면 적자이므로 사용자별 일일 한도, 저가 모델, 컨텍스트 요약 필수 |
| 개인정보 | 광고 도입 시 개인정보 처리방침·이용약관 필요. 번호판·주행 기록이 개인정보일 수 있고, GPT로 전송되는 데이터도 고지 (개인정보보호법 준수) |
| 광고 연동 | 웹은 AdSense 등 광고 정책 준수. 광고 영역은 별도 컴포넌트로 분리해 교체 가능하게 구성 |
| 세금/사업자 | 수익 발생 시 소득 신고, 규모에 따라 사업자 등록 검토 |
| 대안 모델 | 프리미엄 구독(GPT 한도 확대, 광고 제거)이 AI 비용을 감당하기에 더 현실적일 수 있음 |
