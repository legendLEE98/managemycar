# 내차일기 기획서

> 내 차의 주행·주유·정비 이력을 대화로 기록하고, 소모품 교체 시점을 알려주는 차량 관리 웹앱
> 가운데 3D 차량 + Claude 같은 채팅창 (React + Spring Boot + PostgreSQL + GPT API)
> 최종 수정: 2026-11-11 / 상태: v0.3 (핵심 기능 구현 완료, 지도·알림·앱화 예정)

---

## 1. 배경 및 목적

### 1.1 문제 정의
- 정비·주유 기록이 영수증, 메모, 카드 내역 등에 흩어져 있다.
- 엔진오일, 타이어, 브레이크 패드 등 **교체 시점을 놓치기 쉽다.**
- 주행거리를 갱신하지 않으면 교체 시기 계산이 부정확해진다.

### 1.2 목표
1. 차량별 이력을 **말 한마디로 입력**한다.
2. 소모품 교체 상태를 **한눈에** 보여주고, 판단 근거가 되는 **데이터가 부족하면 신호를 준다.**
3. 숫자 계산은 AI가 아니라 **코드가 한다.** AI는 해석과 대화만 맡는다.

### 1.3 핵심 컨셉: 대화형 차량 관리
메뉴와 폼을 헤매지 않고, **차를 보며 말로 기록하고 묻는** 앱이다.
- "오늘 100키로 탔어" → 주행거리 갱신
- "어제 엔진오일 갈았어" → 정비 기록 저장, 소모품 주기 리셋
- "내 차 소모품 상태 알려줘" → 서버가 계산한 상태 표를 근거로 답변 (기록은 하지 않음)
- "엑셀로 내보내 줘" → 대화에서 바로 다운로드

## 3. 기능 현황

### 3.1 구현 완료
| 영역 | 내용 |
|---|---|
| 대화 기록 | GPT function calling으로 차량 등록·주행·주유·정비·주행거리·출퇴근·교체주기 기록. 모호하면 되묻고, 조회성 질문에는 쓰기 도구를 호출하지 않음 |
| 차량 등록 검증 | 차종 카탈로그(257종)로 검증. 없는 차종은 사용자 확인 후 "미확인 차종"으로 등록 |
| 차체 유형 | 경형·소형·준중형·중형·준대형·대형, SUV 4단계, 승합차, 스포츠카, 픽업, 트럭 |
| 연료 구분 | 가솔린·디젤·LPG·하이브리드·전기 등. 연료에 따라 소모품 항목이 달라짐 (전기차: 감속기 오일, 배터리 냉각수 등) |
| 소모품 현황 | 18개 항목, 구간별 교체 주기, 잔여 km/일수 게이지, 상세 모달에서 수기 입력·수정 |
| 데이터 보강 신호 | 차량 정보·주행거리·출퇴근 거리 등 부족한 데이터를 우측 패널에서 안내하고 입력 예시 제공 |
| 주행 모달 | 현재 주행거리(계기판 입력=실측)와 출퇴근 여부·하루 출퇴근 거리 입력 |
| 3D 차량 | 귀여운 저폴리 GLB(Kenney Car Kit), 브랜드 단색, 드래그 회전(자동 회전 없음), 본네트·유리·바퀴·차체 클릭 시 관련 소모품 팝오버 |
| 다중 차량 | 차량 추가(최대 5대), 차량 전환·삭제 |
| 캘린더 | 기록·교체 이력을 날짜별로 확인 |
| 계정 | 자체 회원가입/로그인(Argon2id), 비밀번호 변경, 로그아웃 |
| 서버 저장 | 계정 데이터는 `user_id + version` 스냅샷으로 저장, 변경 이력 조회·되돌리기 |
| 비로그인 체험 | 로컬스토리지에 임시 저장 → 로그인 시 서버로 병합 후 로컬 삭제 |
| 엑셀 내보내기 | 패널 버튼 또는 대화로 요청 (차량 요약·이력·소모품 시트) |
| 사용량 제한 | 분당 6건, 하루 로그인 60건 / 비로그인 20건 (한국 시간 기준) |
| 모바일 | 하단 4단 탭(대화·내 차량 상태·캘린더·지도), 우측 햄버거 메뉴(소개·마이페이지·로그아웃 등) |
| 사이트 소개 | 좌측 사이드바에 서비스 소개, 차량 데이터, 3D 모델 크레딧 |

## 4. 주요 사용자 시나리오

1. **첫 사용**: 로그인 없이 대화로 차량 등록 → 연료를 되묻는 질문에 답 → 소모품 현황 확인
2. **주행 기록**: "오늘 출퇴근 했어" → 저장된 하루 출퇴근 거리로 주행거리 갱신
3. **정비 기록**: "엔진오일 갈았어" → 날짜·주행거리 확인 후 교체 이력 저장, 주기 리셋
4. **소장용 차량**: 출퇴근 안 한다고 말하거나 주행 모달에서 체크 해제 → "출퇴근 안 함"으로 저장되고 재촉 항목이 사라짐
5. **로그인 전환**: 체험 중 쌓은 데이터를 로그인 시 서버로 병합하고 로컬 데이터는 삭제
6. **정정**: 잘못 기록한 값은 수정 모달·되돌리기·변경 이력으로 복구

## 6. 데이터 모델

### 6.1 차량 상태 (CarState JSON)
차량 1대의 모든 정보는 하나의 JSON 문서로 다룬다. 서버는 채팅 요청마다 이 상태를 받아 도구를 실행하고 갱신된 상태를 돌려준다(채팅 자체는 stateless).

| 영역 | 필드 |
|---|---|
| vehicle | bodyType, make, model, modelYear, fuelType, verified |
| odometer | km, source(reported/estimated), updatedAt |
| commute | kmPerDay (null=모름, 0=출퇴근 안 함, 1~500=왕복 하루 거리) |
| fuel | 주유 이력 |
| services | 소모품별 마지막 교체일·주행거리·교체 주기(사용자 조정 가능) |
| events | 변경·기록 이력 |

차고(Garage) = `{ activeId, vehicles[{ id, state }] }`, 최대 5대.

### 6.2 DB (PostgreSQL, Flyway V1~V5)
| 테이블 | 설명 |
|---|---|
| app_user | 계정(이메일, Argon2id 해시, password_changed_at) |
| user_state_version | `(user_id, version)` 유니크, 차고 JSON 스냅샷(JSONB). 저장할 때마다 새 버전 생성 |
| chat_usage | 일별 채팅 사용량(로그인·게스트 구분, 원자적 증가) |

**계산 원칙**: 잔여 km, 잔여 일수, 연비, 상태 판정은 모두 서버/클라이언트 코드가 계산한다. AI는 계산하지 않는다.

## 7. 비기능 요구사항

- **반응형**: PC 기준 디자인 + 모바일 전용 레이아웃(1179px 이하). 앱은 디자인을 분리해 별도 진행
- **보안**: Argon2id(OWASP 최소 기준 이상), 세션은 HttpOnly 쿠키 JWT(Bearer도 지원), 비밀번호 변경 시 이전 토큰 무효화, 로그인 시도 제한
- **개인정보**: GPT에는 차량 상태(번호판 등 불필요한 정보 제외)만 전송. 광고 도입 시 처리방침 필요
- **성능**: Vite 빌드, 엑셀 라이브러리 지연 로딩, 3D는 저폴리 모델

## 8. 기술 스택

| 영역 | 사용 | 비고 |
|---|---|---|
| 프론트엔드 | React 18 + Vite 5 + TypeScript | three.js / @react-three/fiber / drei, exceljs |
| 백엔드 | Java 21 + Spring Boot 3.3 + Gradle | Web, Security, JdbcTemplate/JPA, Flyway, jjwt |
| DB | PostgreSQL 16 | Flyway 마이그레이션 |
| AI | OpenAI Chat Completions (function calling) | 서버에서만 호출. 모델·reasoning 설정은 환경변수 |
| 인증 | 자체 로그인(Argon2id + JWT 쿠키) | 네이버 로그인으로 전환 예정 |
| 배포 | Docker Compose(db, back, front) + nginx | 호스트 nginx 설정은 `deploy/nginx/` |

### 8.1 GPT 연동 설계
```
[React 채팅창] → POST /api/v1/chat { messages, state }
   → [Spring Boot] 분당 제한 → 일일 쿼터 → 시스템 프롬프트(+ 서버 계산 소모품 상태 표)
   → [GPT] function calling
        lookup_vehicle / set_vehicle / log_trip / log_fuel / log_service
        set_odometer / set_commute / set_service_interval / export_excel
   → 서버가 인자를 검증해 상태 갱신 → 답변 + 변경 내역 + 갱신된 state 반환
```
- **서버 검증**: 모델이 상태를 직접 바꾸지 않는다. 모든 도구 인자는 서버가 검증한다.
- **조회 vs 기록**: 상태 질문은 서버가 만든 상태 표로만 답하고, 쓰기 도구는 실제 사건이 있을 때만 호출한다. `log_service`는 날짜/주행거리/방금 중 하나가 필수.
- **차종 검증**: `lookup_vehicle`로 카탈로그를 먼저 조회. 카탈로그의 차체 유형이 우선한다.
- **연료 질문**: 차종을 알게 되면 연료를 먼저 물어본다.
- **한도**: 분당 6건(메모리 기준), 하루 로그인 60 / 비로그인 20(DB, KST 0시 초기화). AI 호출이 실패하면 사용량을 환불한다.
- **LLM 장애 시**: 키워드 기반 폴백(KeywordFallback)으로 기본 기록 처리.

### 8.2 프로젝트 구조
```
mycar/
├─ back/        Spring Boot (Gradle, Docker 빌드)
├─ front/       React + Vite (nginx로 서빙, /api 프록시)
├─ deploy/nginx 호스트 nginx 설정 (diarymycar.site)
├─ md/PLAN.md   기획서
├─ compose.yaml
├─ .env.example
└─ source/      3D 원본 GLB (저장소 미포함)
```

## 10. 리스크 및 대응

|---|---|
| 입력이 번거로워 이탈 | 대화 입력, 기본값, 데이터 보강 신호와 입력 예시 |

| 모바일 3D 부담 | 저폴리 모델, 파트 수 최소화 |
| 소장용 차량의 거리 기반 소모품 | 용도·개월 기준 보정(예정) |
